# Z-Desk 内存基线优化

## 背景与目标

在不改变完整 WPF 桌面呈现、硬件渲染、WorkerW 层级和 Shell 交互的前提下，降低实际对象与后台工作量，并记录可对比的内存诊断数据。目标是改善启动和日常操作的资源使用，而不是通过强制裁剪工作集制造瞬时低数值。

## 已完成范围

- [x] watchdog 在 CLR/WPF 初始化前进入原生等待路径，保留父进程等待和 Explorer 图标恢复语义。
- [x] Shell 图像缓存限制为 256 项和估算 16 MB；`FileEntry` 释放时清理绑定图像引用。
- [x] 添加内存快照诊断，记录工作集、专用工作集、私有提交、托管堆、GC 已提交内存、WPF 渲染信息、布局项和 Shell 图像缓存。
- [x] Shell 右键菜单、QuickLook、二维码识别和辅助计时器按需初始化；修复 QuickLook 延迟创建的异常路径。
- [x] 图标视图优先加载图标；Details、Tiles、Content 或非名称排序时再加载文件元数据。
- [x] 保留虚拟化卸载后的图像引用释放与隐藏布局可视树卸载。
- [x] 空闲回调只记录诊断，不执行强制完整 GC、`EmptyWorkingSet` 或清空全局图标缓存，避免后续交互集中缺页。
- [x] 冻结可冻结的共享主题画刷，减少主题资源的可变对象开销。

## 决策与边界

- [x] 完整 WPF 桌面路径是唯一生产路径；不保留原生桌面命令行实验开关。
- [x] 硬件渲染保持默认；软件渲染仅用于诊断对比。
- [x] 所有布局窗口仍在启动时创建，不延迟或移除既有功能。
- [x] 不修改数据模型、持久化格式、Shell 文件语义、拖放、WorkerW 或多 DPI 行为。

## 验证

- [x] Debug、Release、自包含 SmokeTests 构建通过并运行通过。
- [x] SmokeTests 覆盖入口、图像缓存诊断、图像释放、内存快照、图标视图加载策略和选择滚动行为。
- [x] `git diff --check` 通过。
- [x] 已由用户完成默认 WPF 功能与性能人工验收。

## 结果

功能完整性和交互稳定性优先于最低任务管理器瞬时数字。原生呈现试验未满足完整交互验收，已不作为生产方案或后续承诺保留。
