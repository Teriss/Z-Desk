# 修复布局尺寸损坏与无法展开

## 背景与目标

本机两个布局的展开尺寸已被保存为 220 × 36，未开启自动折叠；主文件和备份均受影响。显示器变化仅是待验证线索。修复过渡尺寸污染，保证展开后完整显示一行图标并可拖拽缩放，恢复本机受影响布局。

## 范围与非目标

布局尺寸、折叠、窗口重建、显示器配置切换、持久化校验、测试和本机恢复。保留现有 JSON、折叠与显示器切换功能，不改文件归属或 Shell 操作，不发布 Release。

## 验证方法

## 风险与待验收

原始触发路径尚未确认；不能以显示器变化的体感替代复现证据。历史恢复按布局 ID 匹配最近有效宽高，不能覆盖历史内容。无对应设备或交互环境时准确记录人工未验证项，保留本计划原名。

## 实施发现

- 原保存路径会将未完成 WPF 布局的窗口 ActualWidth/ActualHeight 写入展开尺寸；窗口重建时的位置事件又可同步触发捕获。现已移除这条尺寸写入路径，并保护创建/重建流程。没有证据证明这是用户每次故障的唯一触发源。
- 配置的活动页签恢复可能改变当前视图，最小尺寸校验必须放在页签恢复之后。
- SmokeTests 曾在桌面已有 Z-Desk 运行时因真实 App 启动的单实例分支提前 exit(0)。测试现使用隔离的资源加载 App，避免提前退出和改动真实应用注册。
